## Your five points

1. **Taskbar flicker at launch:** I can't tell from the logs whether it's Windows or LiteWall. LiteWall plausibly contributes: it pokes Explorer to build the wallpaper layer, parents the windows into it, and starts three GPU players at once. A quick A/B test: run `Start-Process $exe -ArgumentList '--test-pattern'` (no mpv, primary only), then try with just one screen enabled, then all three. Compare how much the taskbar flickers. The likely fixes are showing each window only after its first frame, and starting the players one at a time. Both are in the plan.
2. **Delay and fade-in at startup:** yes, there will be a gap while Windows loads. Startup now waits up to 60 seconds for Explorer instead of exiting. A fade from black is cheap, but it fades from black, not from your old wallpaper. A real crossfade from the static wallpaper needs a much bigger rendering change, so that's later. The first thing to do is avoid the black flash by showing a window only after its first frame.
3. **Stopping a covered monitor's video, per monitor:** that's M6, already planned. Covering one monitor pauses only that monitor, and the logic for it is written. A paused monitor costs about nothing. Freeing a long-covered monitor's memory entirely is a possible later extra.
4. **Still images:** done in step 2. The file picker now lists videos (mp4, mkv, webm, mov, m4v, avi), GIF/WebP, and images (jpg, png, bmp, tiff, avif, jxl). Images stay up as long as the wallpaper is set. Note `.webm` is a video and `.webp` is the image/animation format.
5. **Detaching a monitor with one click:** ticking "Enabled" off for a screen already removes its window, player and decode cost, so the load on the third monitor can go to zero today. Detaching it from Windows itself is a different, riskier feature that rearranges your display layout. It's in the plan as experimental and optional.
